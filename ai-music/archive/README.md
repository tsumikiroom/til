# 生成曲アーカイブ

AI で生成した曲とそのメタデータを保管する場所。後でプロンプトの試行錯誤を振り返れるよう、音源ファイルと一緒に `.md` でメタデータを残す。

## ディレクトリ構成

```
archive/
├── README.md              # このファイル
├── YYYYMMDD_<slug>/       # 1 セッション = 1 ディレクトリ
│   ├── meta.md            # プロンプト・設定・所感
│   ├── 01_<title>.mp3     # 生成された曲 (採用)
│   ├── 02_<title>.mp3
│   └── ...
└── ...
```

セッション単位でディレクトリを切ると、同じプロンプトのバリエーション群を一塊にして眺められる。

## 命名規則

### セッションディレクトリ

`YYYYMMDD_<slug>` 形式。slug は短い英語のキーワード。

例:
- `20260601_drone-ambient-first-try/`
- `20260603_aphex-saw2-style/`
- `20260610_rain-piano/`

### 音源ファイル

`<連番>_<title>.<拡張子>` 形式。

- 連番 (01, 02, ...) でディレクトリ内の順序を保つ
- title は短く、何の曲か分かる程度
- 拡張子は `mp3` (Suno/Udio のデフォルト) または `wav`

例:
- `01_glacier-drift.mp3`
- `02_underwater-piano.mp3`
- `03_loop-attempt.wav`

## メタデータテンプレート (`meta.md`)

各セッションディレクトリに 1 つ置く。下記をコピペして埋める。

```markdown
# YYYYMMDD <セッション名>

## 目的
何を試したかったか (1〜2 行)

## 使用サービス
- サービス: Suno / Udio
- プラン: Free / Pro / Premier / Standard / Pro
- モデルバージョン: (例: Suno v5.5 / Udio v3.5)

## プロンプト

\`\`\`
ここに使ったプロンプトを貼る
\`\`\`

### 派生プロンプト (バリエーション試した場合)

\`\`\`
派生プロンプト 1
\`\`\`

\`\`\`
派生プロンプト 2
\`\`\`

## 設定
- ジャンル / タグ: (UI で選んだ場合)
- 長さ: (例: 2:30)
- インスト指定: yes / no
- seed: (取得できれば)

## 生成ファイル

| ファイル | プロンプト | 所感 |
|---------|----------|------|
| 01_xxx.mp3 | 上記基本プロンプト | 良かった点 / 微妙だった点 |
| 02_yyy.mp3 | 派生 1 | ... |

## 学んだこと
- 何がうまくいったか
- 何がうまくいかなかったか
- 次に試したいこと
```

## .gitignore の検討

音源ファイル (mp3/wav) は git に入れるとリポジトリが膨らむ。判断材料:

- **入れる場合**: バックアップ・他マシン共有・履歴管理が利く。容量に注意 (LFS の検討も)
- **入れない場合**: `archive/*/*.mp3`, `archive/*/*.wav` を `.gitignore` に追加。`meta.md` だけバージョン管理。

**初期推奨**: 音源は git に入れず meta.md だけ管理する。後から気に入った曲だけ別途整理してもよい。

決めたら `til/.gitignore` に下記を追記:

```gitignore
ai-music/archive/**/*.mp3
ai-music/archive/**/*.wav
ai-music/archive/**/*.flac
```

## メタデータの書き方のコツ

- **プロンプトをそのままコピペ** — 後でどの語句が効いたか分析できる
- **「ダメだった理由」も書く** — 失敗例は次の改善のヒント
- **聴いた直後に書く** — 印象は数日で薄れる
- **タグ付け (任意)** — ファイル名や meta.md 内に `#drone` `#piano` `#night` などのキーワードを散らしておくと grep で探せる
